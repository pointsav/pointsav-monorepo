The intellectual spine

An Object is an atom. A Composition is what you build from atoms.

The distinction runs through the entire library. Get it right and every downstream party — architect, property manager, tenant — reads the same specification the same way.

BIM Object — the atom

A single, atomic building-component specification.

One product or entity — a task chair, a desk, a storage pedestal — identified by its IFC 4.3 entity class and its Uniclass 2015 classification at the Products (Pr) or Systems (Ss) level.

It carries manufacturer data and the constraints that apply to it. A BIM Object is never a composed layout — it is the atom that Key Plans are assembled from.

Detail view → manufacturer spec sheet · classification · download formats
COMPOSITION — the assembly

A Key Plan template, assembled from many objects.

A named template built from several BIM Objects to satisfy a design methodology and the applicable building code. Classified one tier up, at Uniclass Elements/functions (EF) or Spaces/locations (SL) level — not a BIM Object itself.

A Composition's detail view resolves to a “Composed from” bill of objects — links to its constituent atoms — with the circulation, lighting and accessibility standards it holds constant.

What one registry enables

Authoritative once — consumed by everyone downstream.

Architects

Start from pre-validated, code-compliant building blocks instead of a blank sheet. Every Object and Key Plan is classified, versioned and inspectable — pull only what the standard already approves.

Property managers

Clean data continuity from design through operations. The same registry version that specified a component carries its property set into facilities management — no re-keying at handover, no orphaned records.

Developers & tenants

Transparent, inspectable specifications. Fit-out begins from an approved Composition — not a blank file — that holds wayfinding, lighting and life-safety standards constant across every leasehold.
